API

How's My SSL? provides a simple HTTP JSON API for developers that want to test clients without a browser experience: https://www.howsmyssl.com/a/check.

The API is free to use to test clients under your control. If you would like to use the API to test your users' browsers on your site, subscribe the domain your code will be making requests from at subscriptions.howsmyssl.com. (Non-profit and student programs are available.)

The returned JSON hash will have at least these keys, but may include more as howsmyssl evolves. Each of these keys map fairly obviously to the HTML version and it can be helpful to understand their meaning. The source code that gathers the client info may also be helpful. All strings returned may contain HTML escaped text.

Two of the keys are about resuming TLS 1.3 sessions. given_psk_key_exchange_modes lists the modes the client sent in its psk_key_exchange_modes extension, in order (psk_dhe_ke, psk_ke), and is empty for clients that didn't send one. psk_without_forward_secrecy_supported is true when a client offering TLS 1.3 lists psk_ke, which lets a session be resumed without a new key exchange, and so without forward secrecy. It does not affect rating. A client offering TLS 1.3 that lists either mode is reported with session_ticket_supported as true.

Five of the keys report other things the client's ClientHello says. None of them affects rating. server_name_sent is true when the client sent a server name (SNI); the name itself is not returned. given_alpn_protocols lists the application protocols the client offered with ALPN, in order. Any byte in a protocol name that isn't an ASCII letter, a digit, or one of -._/+ is returned as \xNN, at most 16 protocols are returned, and names longer than 32 bytes are cut short and end in  (truncated). secure_renegotiation_supported is true when the client sent the renegotiation_info extension or the TLS_EMPTY_RENEGOTIATION_INFO_SCSV cipher suite (RFC 5746). given_key_share_groups lists the named groups the client sent a TLS 1.3 key share for in its first ClientHello, in order, at most 16 of them; it is empty for clients that sent none. encrypted_client_hello_offered is true when the client sent the encrypted_client_hello extension (RFC 9849), whether as a real offer or as the GREASE placeholder, which can't be told apart from here.

Let me be a little more explicit. How's My SSL is Open Source software and can be found on GitHub. There's a README.

Just Need the TLS Version?

If all you need is the TLS version of the client, the preferred way to get it is tlsversion.com. Its JSON API returns just the version, without the rest of the analysis How's My SSL? performs:

    GET https://www.tlsversion.com/v1/version.json HTTP/1.1

    {
      "version": "TLS 1.3"
    }
